Este site tem dois trabalhos: dizer a um recrutador, em menos de um minuto, o
que eu faço, e ser prova disso. O segundo trabalho significa que o próprio
build faz parte do portfólio, então aqui está como ele é montado. Cada
escolha abaixo tem um registro de decisão curto no
[repositório](https://github.com/lima300/portfolio/tree/main/docs/adr),
com o que foi descartado e quanto ela custa.

## A stack

- **[Next.js 16](https://github.com/lima300/portfolio/blob/main/docs/adr/0001-stack.md)**
  com App Router, React Server Components e Cache Components. Toda página é
  pré-renderizada como HTML estático; o único JavaScript enviado é o das
  poucas coisas com que você realmente interage.
- **TypeScript** em modo `strict`, inclusive para o conteúdo: cargos, métricas
  e traduções são dados tipados, então uma tradução faltando é erro de
  compilação, e não um espaço em branco.
- **[Tailwind CSS v4](https://github.com/lima300/portfolio/blob/main/docs/adr/0003-design-tokens.md)**,
  guiado por design tokens definidos uma vez como propriedades CSS. Claro,
  escuro e "seguir o sistema" são três estados reais, e a escolha manual
  vence nas duas direções.
- **[MDX](https://github.com/lima300/portfolio/blob/main/docs/adr/0005-mdx-prose-typed-facts.md)**
  para os textos longos, como os cases e esta página. Os fatos que essas
  páginas mostram vêm dos mesmos registros tipados que todo o resto.
- **Inter** e **JetBrains Mono**, hospedadas pelo próprio site com
  `next/font`, então não há requisição a um serviço de fontes nem salto de
  layout quando elas carregam.

## O que fica de fora, de propósito

- **Nenhuma biblioteca de i18n.** [Inglês e português](https://github.com/lima300/portfolio/blob/main/docs/adr/0002-native-i18n.md)
  são dicionários tipados sobre as primitivas de roteamento do próprio Next.
  O português precisa ter exatamente as mesmas chaves do inglês, ou o build
  falha.
- **Nenhuma biblioteca de animação.** O [movimento](https://github.com/lima300/portfolio/blob/main/docs/adr/0004-native-motion.md)
  é feito com animações CSS guiadas por scroll, a View Transitions API na
  troca de tema e algumas poucas primitivas nativas. Tudo respeita a opção
  de _reduzir movimento_, e o site fica completo sem ele.
- **Nenhum analytics e nenhum cookie.** Nada neste site segue você.

## Como ele é cobrado

Todo pull request, e todo push na `main`, passa pelos mesmos portões na CI:

- **Formatação, lint e tipos:** Prettier, ESLint e TypeScript, sem nenhum
  aviso permitido.
- **Testes unitários** para os dados e os utilitários, incluindo um teste de
  contraste que lê os tokens de cor reais e verifica cada par de texto sobre
  superfície contra o WCAG AA, nos dois temas.
- **Testes ponta a ponta** no Chromium e no WebKit, contra um build de
  produção e contra o servidor de desenvolvimento, incluindo uma varredura
  automática de acessibilidade de cada página principal contra o WCAG 2.2 AA
  e uma verificação de que nada é registrado no console do navegador.

As metas para as quais ele é construído são nota 95 ou mais no Lighthouse em
mobile e menos de 120 kB de JavaScript no primeiro carregamento.
